🎯 一、Docker 解决什么痛点？
-------------------

开发经典噩梦：本地代码正常运行，换到同事电脑/服务器直接崩溃报错。

常见问题：

*   📌 软件版本不一致
*   📌 项目依赖库缺失
*   📌 操作系统环境差异

Docker 核心思路💡：把**程序 + 整套运行环境**打包成独立容器。  
一次打包，任意机器开箱即用，运行效果完全统一，彻底解决环境不一致难题。

🔑 二、Docker 三大核心概念
------------------

### 📦 1. 镜像（Image）

静态只读模板，相当于预装环境与程序的安装包，本身不可修改，是创建容器的底层模板。

### 🚀 2. 容器（Container）

镜像运行后生成的**运行实例**。

*   一个镜像可同时启动多个容器，容器之间完全隔离互不干扰；单个容器宕机不会影响其他服务
*   底层原理：镜像只读，容器启动会叠加一层**可写层**，所有修改仅保存在这一层，不会改动原始镜像；删除容器后，可写层数据默认丢失

**🥘 形象比喻**

镜像 = 菜谱（静态模板）  
容器 = 按菜谱做出的菜品（运行实例）

### 🏬 3. 仓库（Registry）

Docker Hub 是主流公共仓库，等同于 Docker 应用商店，MySQL、Nginx、Node 等官方镜像可直接下载使用。

### 🔗 三者完整工作主线

从仓库拉取镜像 → 使用镜像启动生成容器

✅ 三、Docker 安装验证 & 容器基础操作
------------------------

### 1\. 验证 Docker 是否安装成功

终端执行命令：

```
docker run hello-world
```

执行流程：

1.  本地检索 `hello-world` 镜像，不存在则自动连接 Docker Hub 下载（拉取镜像）
2.  下载完成自动启动容器
3.  控制台输出 `Hello from Docker!` 后容器正常退出，出现该文字即代表安装就绪

### 📋 容器生命周期常用命令

| 命令 | 作用 |
| --- | --- |
| `docker ps` | 🔍 查看当前正在运行的容器 |
| `docker ps -a` | 📜 查看所有容器（包含已停止的） |
| `docker run` | ▶️ 创建并启动新容器 |
| `docker stop [容器名/ID]` | ⏸️ 停止运行中的容器（容器保留，数据不丢失） |
| `docker start [容器名/ID]` | ▶️ 重启已停止的容器 |
| `docker rm [容器名/ID]` | 🗑️ 彻底删除容器（容器及默认存储数据全部清除） |
| `docker logs [容器名/ID]` | 📝 查看容器运行日志，排查报错核心工具 |
| `docker exec -it [容器名/ID] /bin/bash` | 🔧 进入运行中容器内部，调试文件、查看配置 |

🌐 四、端口映射（外部访问容器服务）
-------------------

容器自带网络隔离，内部端口外部无法直接访问，需要**端口映射**打通内外通道。

### 参数 `-p` 格式

`宿主机端口:容器内部端口`

```
-p 8080:80
```

含义：访问本机 `8080` 端口，流量自动转发至容器内部 `80` 端口

⚠️ 注意：冒号前为宿主机对外开放端口，后为容器内部端口，不可写反

访问方式：浏览器打开 `localhost:8080` 即可访问容器内网站服务

💾 五、数据卷（持久化存储，防止数据丢失）
----------------------

### ❌ 存在问题

容器删除后，容器可写层内所有数据会永久丢失，数据库等核心业务数据不能丢失。

### ✅ 解决方案：数据卷（参数 `-v`）

将宿主机本地目录挂载绑定容器内部目录，数据存储在宿主机硬盘，和容器完全解耦。

### 挂载格式

`宿主机本地目录:容器内存储目录`

```
-v /data/mysql:/var/lib/mysql
```

效果：容器写入 `/var/lib/mysql` 的数据实际保存在宿主机 `/data/mysql`  
即使删除容器，重新创建并挂载同一目录，原有数据完整保留。

**核心分工：**

*   🧩 容器：负责运行程序服务
*   💽 数据卷：负责持久化存储业务数据

🛠️ 六、自定义镜像：Dockerfile 打包项目
---------------------------

### 📄 Dockerfile 定义

镜像打包说明书，一行一条构建指令，基于基础镜像构建专属项目镜像。

### 标准示例

```
# 基础镜像：基于预装node18的官方镜像构建
FROM node:18
# 设置容器内部工作目录，后续操作均在此目录执行
WORKDIR /app
# 将本地项目代码复制到镜像内工作目录
COPY . .
# 构建镜像阶段执行：安装项目依赖
RUN npm install
# 容器启动时默认执行命令，运行项目服务
CMD ["node", "app.js"]
```

### ⚖️ 关键区分

*   `RUN`：🏗️ **构建镜像时执行**，仅打包阶段运行一次
*   `CMD`：🚀 **容器启动时执行**，每次启动容器都会运行

### 构建镜像命令

```
docker build -t myapp .
```

*   `-t myapp`：给自定义镜像命名为 myapp
*   末尾 `.`：使用当前目录作为构建上下文

### ⚡ 镜像分层缓存机制

Dockerfile 每一条指令生成一层镜像，分层设计带来缓存优势：

1.  仅修改变更指令及上层内容，未改动层直接复用缓存，构建速度极快
2.  💡 优化技巧：不常变动的指令写在文件靠前位置，业务代码等高频修改内容放末尾，最大化利用缓存

🧩 七、多容器编排：Docker Compose
-------------------------

### 📌 适用场景

项目通常由多服务组合（网站 + MySQL + Redis 等），手动逐个 `docker run` 配置繁琐、网络难以互通。  
Docker Compose 用配置文件统一管理一组容器，自动组网、一键启停。

### 配置文件 `docker-compose.yml` 示例

```
services:
  # 前端/网站服务
  web:
    build: . # 使用当前目录Dockerfile构建镜像
    ports:
      - "8080:80" # 端口映射
  # 数据库服务
  db:
    image: mysql:5.7 # 直接拉取官方镜像启动
    volumes:
      - ./mysql-data:/var/lib/mysql # 数据持久化挂载
```

### Compose 核心命令

```
# 🚀 一键启动所有服务，自动创建网络、容器
docker compose up

# 🧹 一键停止并清理所有容器、网络
docker compose down
```
